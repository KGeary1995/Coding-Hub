# Repository audit — 26 October 2026

Reviewed Trace 1.11.0 on macOS. The review began at `27cffa1`; commit `d9b2e5c7e00b54d0d138bb27aeb972ee73a9352b` appeared during the review. Its clipboard changes were also inspected, and typecheck/unit checks were repeated. No application fixes were made. This report is the only repository change made by the audit.

The review covered the Electron/preload boundary, CLI discovery and authentication, process lifecycle, structured chat, terminal rendering, repository operations, rules/configuration/memory, usage and device synchronization, phone and linked-computer access, backups, design/coaching/workbench features, and build/release workflows. Generated bundles, dependency source, and private user data were outside source-review scope. Test fixtures used temporary data. The existing application listening on port 47821 was left running.

This is a broad source and execution audit, not proof that every possible defect has been found. Actual provider inference/OAuth, a Windows installation, Intel Mac execution, notarization, and physical-phone/Tailscale delivery were not exercised.

## High-priority defects

### F01 — A failed chat spawn can terminate the whole host

Location: [chat-process.ts](../electron/services/chat/chat-process.ts#L13).

`spawnChatProcess()` never attaches an `error` listener to the child process. When spawning fails, `child.pid` is absent and the function throws, but Node subsequently emits the child's asynchronous `error` event. The surrounding launch catch cannot catch that event. Losing the executable or working directory between discovery and spawn, or an OS-level spawn failure, can therefore crash Trace and disrupt unrelated sessions.

Reproduction: start the adapter with a nonexistent executable inside a subprocess and catch its synchronous exception. The subprocess still exits with status 1 and `Unhandled 'error' event`.

Fix: handle child errors immediately, model startup failure through the adapter's lifecycle, and ensure the run reservation and any prepared resources are cleaned up exactly once.

### F02 — A revoked computer can finish minting a new phone key

Location: [remote-server.ts](../electron/services/remote/remote-server.ts#L418).

Authentication occurs before the handler awaits the request body. `/api/phone-key` then uses the captured computer identity without checking whether that identity still exists. This differs from `/api/input` and `/api/control`, which recheck revocation after reading the body.

Reproduction: authenticate a computer, begin a partial phone-key POST, revoke the computer, and finish the POST body. The request returns a fresh token that successfully reads `/api/channels`. This requires a previously authorized computer and the revocation race; it is not an unauthenticated bypass.

Fix: revalidate current authorization after every asynchronous boundary before granting access or mutating state, especially for both key-minting endpoints. Add a regression covering a request body arriving across revocation.

## Medium-priority defects

### F03 — Relay-key length validation can make every device unreadable

Locations: [stored-device schema](../electron/services/remote/remote-server.ts#L45), [key creation](../electron/services/remote/remote-server.ts#L421).

The incoming relay key permits 100 characters. The stored key is `${device.id}:${relayKey}`, but the stored schema also permits only 100 characters. A valid 64-character input becomes 101 characters after adding the UUID and colon. `save()` writes it without validating the complete registry. The immediate status lookup fails, and subsequent registry reads throw `LOCAL_DATA`.

Reproduction: a paired computer sends a 64-character relay key. The response is 500; `remote.status()` then reports that `remote-devices.json` cannot be read. Normal first-party phone IDs are shorter, but this endpoint accepts the damaging request as valid.

Fix: align input and persisted limits, validate the entire replacement document before writing, and retain the previous readable file on validation failure.

### F04 — Header interruption corrupts the chat protocol

Locations: [SessionTile.tsx](../src/components/SessionTile.tsx#L112), [PtyManager.write](../electron/services/cli/pty-manager.ts#L288), [structured interrupt](../electron/services/cli/pty-manager.ts#L238).

The channel header uses `writeTerminal(id, '\x03')` for every running channel. Chat runs also acquire a terminal entry through `routeTerminalEvent()`, and the host's ordinary write endpoint accepts them. Their process uses pipes, so ETX is a byte in a JSON stream rather than a terminal-generated SIGINT. It can be prepended to the next JSON message and cause that message to be rejected. ChatView's own stop-reply button already uses the correct structured interrupt endpoint.

Reproduction: start a mocked chat run and invoke the ordinary write endpoint. Its child receives the literal ETX byte.

Fix: route chat header interruptions through the chat API and reject raw terminal writes for chat runs at the host boundary.

### F05 — Chat has no recoverable transcript inside Trace

Locations: [chat routing](../electron/services/cli/pty-manager.ts#L220), [host storage routing](../electron/main.ts#L95), [chat store](../src/state/chat-store.ts#L14), [saved workspace](../src/state/workspace-store.ts#L177).

Structured replies are sent only through `onChat`. History output is saved only from `SessionEvent.data`, which chat does not emit. The chat store is memory-only and is absent from the saved-workspace schema. A chat run can therefore have a history row with an empty output log, while reload/restart clears its displayed messages and images. Resume starts with a notice rather than loading the native transcript. Provider-owned transcripts may still exist; this is loss of Trace's visible/recoverable conversation, not proof that the provider deleted it.

Reproduction: feed an assistant reply into a chat run. A ChatEvent is emitted, but no session-data event is emitted for storage.

Fix: persist a bounded structured transcript, or load native conversation history when resuming. Make history/export/search semantics explicit for chat runs.

### F06 — Remote chat channels look available but have no usable conversation

Locations: [host onChat callback](../electron/main.ts#L111), [remote input rejection](../electron/services/cli/pty-manager.ts#L99), [remote channel contract](../shared/remote.ts#L7).

Remote channel lists distinguish engines but do not distinguish terminal and chat modes. Chat output bypasses the remote server and linked computers, so these channels show an empty terminal. `writeRemote()` explicitly rejects chat input. A chat approval can still raise a phone notification and appear as waiting, but the phone cannot approve it.

Fix: transport structured chat and approval actions remotely, or mark/filter unsupported chat channels and stop implying that their approval prompts can be answered from the phone. Treat this as a feature gap with misleading current presentation.

### F07 — Removed chat conversations and images remain allocated

Locations: [chatForget](../src/state/chat-store.ts#L31), [session removal](../src/state/workspace-store.ts#L155), [runtime cleanup](../src/runtime/use-native-host.ts).

`chatForget()` is defined but never called. Removing a chat tile cleans up terminal state but leaves its thread, image data URLs, tool results, and messages in the global chat store. Repeatedly opening and closing image-heavy chats can grow memory indefinitely even though the workspace permits only eight simultaneous tiles. Active conversations are also unbounded and rendered in full on each update.

Fix: release removed threads, define retention bounds, and consider incremental rendering for long active conversations. Verify with repeated add/send/remove cycles rather than only a short chat fixture.

### F08 — Interrupted Codex approvals remain actionable

Locations: [Codex completion handling](../electron/services/chat/codex-stream.ts#L99), [UI completion handling](../src/state/chat-store.ts#L70).

`turn/completed` clears `turnId` and emits `done`, but does not clear outstanding approval requests or emit `permission-done`. The UI's `done` handler also leaves permissions untouched. An interrupted turn can therefore leave an Allow button for a request that no longer belongs to an active turn.

Reproduction: inject an approval request followed by an interrupted-turn notification. No permission-closure event is emitted, and `answer()` still accepts the old request ID.

Fix: track requests by turn, handle cancellation/resolution notifications, and close remaining permissions when their turn ends.

### F09 — Native-history bounding occurs before recency ordering

Location: [native-sessions.ts](../electron/services/workbench/native-sessions.ts#L12).

Directory traversal stops at 500 results or 4,000 visited entries, across all engines and profiles. Results are sorted by modification time only afterward. Earlier traversal entries consume the budget before newer entries are considered. The default Claude tree is scanned before Codex and named Claude profiles, so a large Claude history can prevent those sources from appearing at all. `source()` uses this same scan, so the problem can block a saved tile's resume, not merely omit a list row.

Reproduction: create 501 Claude files, mark the last one newest, and create a Codex conversation. The list contains 500 older Claude entries, omits the newest one, and contains no Codex entry.

Fix: apply fair per-source enumeration and select the most recent bounded results. Resolve a known conversation ID directly rather than requiring it to survive a global history list.

### F10 — Incomplete usage disappears from cross-computer sync

Locations: [strict usage schema](../electron/services/hub/device-sync.ts#L26), [publication filter](../electron/services/hub/device-sync.ts#L160).

`UsageRecord.incomplete` is supported by telemetry and the UI, but absent from the strict sync schema. Publication removes `days`, then silently drops every record that fails validation. A run with `incomplete: true` is excluded entirely instead of being sent with its warning.

Reproduction: supply one otherwise valid incomplete record to DeviceSync. Its published usage array is empty.

Fix: share a compatible usage schema, preserve the incomplete flag, and report validation failures rather than quietly deleting records from the published view.

### F11 — Synced cost estimates remain tied to the sending computer

Locations: [remote usage import](../electron/services/hub/device-sync.ts#L169), [combined usage response](../electron/services/hub/service.ts#L73), [usage refresh](../src/runtime/use-native-host.ts#L20).

Local telemetry recalculates cost from the current price settings. Remote usage is imported with its already-computed `cost` and returned unchanged. Updating rates therefore reprices local runs while leaving remote runs at an old price, even though the UI says estimates use configured rates. A settings-only sync need not rewrite the remote usage file before the receiving computer displays the new settings.

Reproduction: sync a remote record priced at $1 into a computer whose applicable configured rates are all zero. `otherUsage()` still returns $1.

Fix: preserve sufficient event/model information to price imported records consistently, or explicitly label remote estimates with their source pricing and calculation time. Simply applying the final model to a multi-model run may still be inaccurate.

### F12 — Named-profile restore cannot fulfill saved resume references

Locations: [backup allowlist](../electron/services/workbench/backups.ts#L14), [backup nested additions](../electron/services/workbench/backups.ts#L84), [profile directory](../electron/services/cli/claude-profiles.ts#L65), [resume gate](../electron/main.ts#L113).

The backup includes the named-profile label registry and saved workspace, including `resumeId`, but excludes the profiles' `projects/**` conversation files. After restore, `CLAUDE_CONFIG_DIR` points into the new restore directory. Signing in again does not recreate those local transcripts. The resume gate cannot find the saved conversation there and refuses to launch that tile until its resume setting is cleared or transcripts are manually recovered.

Fix: include noncredential profile conversation history with an explicit size/privacy policy, or clear unsupported resume references during restore and explain why. This is separate from the intentional exclusion of credentials.

### F13 — Close/quit can leave a failed login process behind without asking

Locations: [window close](../electron/main.ts#L300), [application quit](../electron/main.ts#L612), [login shutdown](../electron/services/cli/account-login-manager.ts#L79).

Both shutdown paths catch failures from stopping coding and login processes together. They then inspect only PtyManager process IDs. If `accounts.stopOwner()` or `accounts.close()` fails while a login process remains alive, there may be no coding PID, so the window is destroyed or the application quits without the remaining-process choice. The login manager retains the run but exposes no PID list to this guard.

Fix: account for all owned login and coding processes when deciding whether shutdown succeeded, and retain an actionable owner/PID until termination is verified.

### F14 — Default desktop screenshot comparison fails on Retina displays

Locations: [capture](../electron/services/workbench/live-preview.ts#L54), [comparison limit](../electron/services/workbench/live-preview.ts#L26), [default viewport](../src/components/DesignReviewPanel.tsx#L10), [failing smoke assertion](../scripts/productivity-smoke.cjs#L82).

Capture saves device pixels, while viewport selection uses CSS pixels. On this 2× display, a 400×500 viewport produced an 800,000-pixel image, not 200,000. At the offered/default 1440×900 desktop viewport, the same scaling produces 2880×1800 = 5,184,000 pixels, above the comparison service's four-million-pixel cap. Two otherwise valid captures at the same offered viewport are rejected.

Fix: normalize captures to a declared pixel scale, expose limits in CSS/display-independent terms, or adjust the limit consistently. Make the smoke test assert captured dimensions rather than assume a 1× display.

### F15 — Short runs can lose their automatic memory summary

Locations: [exit ordering](../electron/main.ts#L103), [final transcript discovery](../electron/services/hub/telemetry.ts#L165), [summary inputs](../electron/services/hub/auto-memory.ts#L183).

The exit callback asks telemetry for the transcript path and passes that value to AutoMemory before invoking telemetry's final poll. Final polling is expressly allowed to discover a short run's transcript. When it does, AutoMemory has already received `null`; a conversation-only run with no Git changes can produce no summary even though its last assistant message is now available on disk.

Fix: finalize transcript discovery before constructing the summary input and return the discovered path before removing the watcher. Exercise a run whose transcript appears immediately before exit.

### F16 — Final incomplete flags do not reach the live renderer

Location: [TelemetryService.finish](../electron/services/hub/telemetry.ts#L184).

When final reading cannot reach the captured target size, `finish()` sets `metadata.incomplete` in SQLite but does not publish an updated UsageRecord. The renderer keeps its last published record and can present partial totals without the warning until a later explicit/background reload.

Reproduction: read one usage event, append another, simulate a locked transcript during `end()`, and compare results. `list()` returns `incomplete: true`; the last published record has no incomplete flag.

Fix: publish final state after finalization, including warning-only changes, and make error paths with missing/unstatable files explicitly represent uncertain completeness.

## Additional shortfalls

| ID | Priority | Shortfall, impact, and suggested follow-up |
| --- | --- | --- |
| S01 | Low | **Backup restore changes the computer's sync identity.** [The allowlist](../electron/services/workbench/backups.ts#L14) omits nonsecret `machine.json`; [DeviceSync](../electron/services/hub/device-sync.ts#L87) generates another identity after activation. Reproduced by backup/restore. Other computers can retain a stale identity for the same address, and relinking can encounter identity mismatches. Define explicit same-computer restore versus migration behavior; preserve or deliberately remap identity. Excluding pairing credentials can remain intentional. |
| S02 | Low | **Several caps have no supported cleanup path.** [Backups](../electron/services/workbench/backups.ts#L63) stop at 50 index entries but expose no delete operation; deleting a bundle outside the app does not remove its index entry. [Rules](../electron/services/hub/rules.ts#L99) permanently union user-project registrations and stop at 100 without unregistering them. Tasks, experiments, and design versions likewise have caps without corresponding delete/archive operations. Add retention or removal rather than requiring manual JSON edits. |
| S03 | Low | **Daily usage has inconsistent definitions.** [Status-bar totals](../src/state/channel-state.ts#L74) use per-day data; [Usage windows and bars](../src/state/usage-summary.ts#L17) use session start and whole-run totals, and explicitly document that convention. For a run spanning midnight, “Today” can disagree between screens. Codex's cumulative snapshot is attributed wholesale to its latest reported day in telemetry, which can also overstate today's activity. Preserve daily deltas if the product intends activity-by-day accounting. |
| S04 | Low | **Phone offline startup is not guaranteed after the first visit.** [The service worker](../phone/public/sw.js#L4) caches only requests it intercepts and has no shell precache in its install step. Its first registration happens after the initial page/assets load. A phone that has paired and collected sibling keys can still lack a cached HTML/JS shell when its home computer first goes offline. Precache a versioned complete shell and verify first-visit → offline → sibling connection. This was traced, not tested on a physical phone. |
| S05 | Low | **Connected streams have no liveness timeout.** [Phone follow](../phone/api.ts#L119) times out only before stream headers arrive; it then waits indefinitely for `reader.read()`. LinkedComputers similarly waits for stream reads without a heartbeat watchdog. A network path that silently stalls can leave the UI “live” and delay failover until the platform's own TCP timeout. Add an idle deadline based on the server's 25-second heartbeat. |
| S06 | Low | **Configuration inventory does not follow named Claude profiles.** [ConfigService](../electron/services/hub/config.ts#L45) has one default Claude home and accepts only a directory, whereas [profile launches](../electron/services/cli/claude-profiles.ts#L73) use a separate `CLAUDE_CONFIG_DIR`. Inventory/toggles can therefore describe the default account's tools rather than those used by a named-profile channel. Add a profile context or clearly label the scope. |
| S07 | Low | **Chat protocol input is not safely validated.** [ClaudeStream](../electron/services/chat/claude-stream.ts#L45) and [CodexStream](../electron/services/chat/codex-stream.ts#L62) catch JSON syntax errors but trust the parsed envelope. Valid JSON `null` reaches property access and throws out of the stdout listener. There are also no initialization/request deadlines, and Codex's initialize callback proceeds even on an error response. Validate envelopes, isolate parser errors from host lifecycle, and fail stalled startup visibly. The null-envelope exception was verified directly; real-provider occurrence was not demonstrated. |
| S08 | Low | **Build tooling has one known advisory chain.** The registry audit reported three moderate affected package entries: `postcss-selector-parser`, `postcss-nested`, and `tailwindcss`. These are one inherited selector-parsing CPU-exhaustion advisory, not three independent exploits. Production-only audit reported zero. Review a compatible parser override or a tested Tailwind upgrade; do not blindly apply the suggested major upgrade. [Advisory](https://github.com/advisories/GHSA-rj75-hqrm-r3gf). |
| S09 | Low | **Public Mac release publication is not gated on Developer ID signing/notarization.** [The release workflow](../.github/workflows/release.yml) passes no Mac signing/notarization inputs; [the builder](../electron-builder.cjs) defaults to ad-hoc signing without them. The publish job accepts the resulting artifacts. Historical handoffs describe manually replacing those images afterward, but that process is outside the automated gate. Gate public publication on the intended signature/notarization checks, or make the manual artifact handoff an explicit release stage. Hosted release assets were not inspected in this audit. |

## Suggested repair order

1. Fix host crash handling, key-minting revocation checks, and registry validation before the next release.
2. Repair chat interruption, approval lifecycle, transcript recovery, remote presentation, and memory cleanup together, with a real structured-chat integration fixture.
3. Fix history enumeration and restore/resume behavior, then telemetry finalization and synchronization compatibility.
4. Normalize capture scaling, make smoke tests platform-independent, and add cleanup/retention workflows.

No application or dependency changes, commits, release builds, publications, or operations on the user's running sessions were performed by this audit.
