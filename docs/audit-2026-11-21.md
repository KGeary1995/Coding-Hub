# Audit of Trace 1.25.0 and its fixes (21 November 2026)

This records the audit of `main` at `e54e12a` (1.25.0, the same commit as GitHub and the installed app) and what was changed on the branch `fix/audit-2026-11-21`. It started from one report: a console window flashed on Windows every so often, over a full-screen game.

## How it was done

- **Six read-only audits, one per area**, all by Fable 5.2: main process and IPC; CLI and chat services; hub and storage; phone and linked computers; repository, workbench, updates and release; the renderer.
- **Five fix packages by Sonnet**, each given separate files. Fable 5.2 read every diff against the finding it answers before accepting it, and made three small changes itself (noted below).
- **Compared with GitHub:** no open pull requests, one open issue (#19), CI and the 1.25.0 release runs green.
- **Nothing was run on a Mac, on a real phone, on a linked computer or in the installed app.** See "Not verified".

## The console window

**Cause.** Since 1.25.0 the plan-limits check runs `agy -p /usage --output-format json`. Any run of agy checks for its own update, at most every 15 minutes: it starts a detached `agy --bg-updater`, and that one starts `agy --version` with no console to inherit. Windows gives it a new one and shows it (a Windows Terminal window where that is the default terminal). `windowsHide` covers only the direct child, so Trace's own spawn options cannot stop it.

**Evidence.** A recorder of every new top-level window and process caught the chain from the installed Trace itself (`Trace.exe` → `agy -p /usage` → `agy --bg-updater` → `agy` → `WindowsTerminal.exe -Embedding`, visible window). agy's log for each such run says `auto_updater.go:372] Spawned background update process`. The Claude and Codex checks showed no window.

**Fix.** `probeCLI` (`electron/services/cli/discovery.ts`) sets `AGY_CLI_DISABLE_AUTO_UPDATE=true` for every background question (`PROBE_ENVIRONMENT`). With it agy logs `Auto-update disabled via environment variable` and starts no updater. The value must be `true`; `1` changes nothing. A channel's own agy is started without it and still updates itself.

**Still there, outside Trace:** starting a Gemini channel, or running agy in any terminal, can show the same window (at most once per 15 minutes). That is agy's fault to fix. Any other program that runs agy on a timer shows it too.

## Left as it is

- **A background shell command does not hold a turn open** (only subagents do): it may run for ever.
- **`electron-updater` runs PowerShell without `windowsHide`** after a download when a build names a publisher. Today's builds do not; it would show once per update when signing is turned on.
- **Background timers run while Trace is minimised** (`backgroundThrottling: false`): plan limits every five minutes, Git every 30 seconds while a sent task is open. All hidden; left as designed.
- **A Trace before this version** that does not know the phone-key revocation request is asked again at every connection until the link is removed.

## Not verified

- Anything on a Mac, a real phone or a linked computer: the Cmd hints, the phone's Screen and Conversation changes, the revocation retry and the screen-service check against real Tailscale.
- The installed app: the console window fix was shown with agy run as Trace runs it and by a unit test of `probeCLI`, not in an installed build.
- The new tests were not all run against the old code. The two "left running" tests were; they failed before the fix.
